# E2E 覆蓋矩陣（第一批，2026-10-02）

[English](2026-10-02-e2e-coverage-matrix.md) | **繁體中文**

本批沒有可直接刪除的案例。相同業務規則已有 unit／integration assertion，但下列 E2E 仍檢查畫面、focus、導頁、事件時序或 Undo wiring；這些不是函式與 API 測試的重複覆蓋。判定「僅加速準備」代表未來可用 API 建立 fixture，仍保留原本 UI 操作與 assertion。本階段沒有改準備方式、刪除案例或增加 workers。

下表的 composer 案例都在 `tests/e2e/document-composer.spec.ts`，organize 案例都在 `tests/e2e/zz-organize.spec.ts`。替代測試檔案使用 repo 相對路徑，case title 為精確原文。「會抓到的缺陷」只列既有替代 assertion 真正能抓到的缺陷，不表示能取代整個 E2E。

| organize: `a folder the document is asked to go into that is gone is refused in words, not with a blank page` | `tests/integration/organize-api.test.ts`: `does not go into an archived folder, or one in another source, and answers 404 for one that is not there`；move route 另有 `refuses a destination that is archived, or is not a folder`；`tests/unit/organize-messages.test.ts`: `it.each`：`INVALID_PARENT` → `no longer exists\|archived` | New document here 帶 folder query、folder 同時 archive、Create 顯示 alert、留在原 URL、沒有多餘 access recheck | 僅加速準備：最初 folder 可 API 建立 | create API 接受 archived destination；move API 錯接受 destination（不同 route） | create 表單 404 與 input 保留整合；move refusal 不能替代 create refusal |

Rename、move、create 與 archive 的拒絕分屬不同 route 與不同 UI；不得僅憑「都有 404」合併。`organize-api.test.ts` 的 `refuses an archived folder, and a document's node` 是 rename 防線；`refuses a destination that is archived, or is not a folder` 是 move 防線；新文件表單拒絕則須搭配 create case。

下一階段優先候選是 organize 的純 fixture 建立：非空 folder 拒絕、archive／Undo 案例中非受測的 sibling、vanishing-folder 的最初 folder。需先量測 setup／assertion 分段；保留 New document here、archive、Undo、toast、access-check assertions。Composer 多數 `createNote` 已經用 API，不能再把它計為新的加速收益。其餘 composer 的鍵盤與渲染時序案例目前不選為移層刪除候選。
