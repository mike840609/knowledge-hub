## 下一階段具體輸入

先依[覆蓋矩陣](2026-10-02-e2e-coverage-matrix.md)選 API fixture 準備，不先刪除 UI cases：

1. `zz-organize.spec.ts` 的 `a folder that still holds something is not archived, and the reader is told what to do`：folder／document 是 setup；用 `/api/workspaces/:workspaceId/folders` 與 documents route 建立後，保留 archive 拒絕 toast、ACTIVE tree、無 access recheck、menu 與後續 archive 成功 assertions。Folder route 已由 `tests/integration/organize-api.test.ts` 匯入驗證；實作時用回傳 node id 串接 tree 操作。
2. `are made inside a folder, archived with an Undo that takes the reader back, and restored to the same place`：只有 folder／非受測 sibling 可以用 API；第一篇 New document here、archive 導頁與 Undo 導回及順序必須繼續由 browser 驗證。
3. `a folder the document is asked to go into that is gone is refused in words, not with a blank page`：最初 folder 可 API 建立；New document here query、並發 archive、Create 拒絕與 input／URL／access assertions 保留。
4. Composer 的 `createNote` 已用 `page.request.post`；其保存與渲染／keyboard race 留在 E2E，沒有可再次移除的 UI setup。

隔離／shard 計畫必須處理的共享資料：

- `tests/e2e/fixtures/organize.ts::mySpace` 導向固定 local E2E user 的 My Space；`openKnowledge` 每次加入 seed document。`zz-organize.spec.ts` 的檔案註解明確依賴排序，避免新增文件影響 `workspace-graph.spec.ts` hover 的 graph 位置；unique title 不會隔離 graph 的節點集合與幾何位置。
- `workspace-graph.spec.ts` 會 hover SVG node，zoom／pan 並檢查 transform；把 graph 與同一 My Space 的 authoring／organize 並行會改 layout。先按 spec 使用獨立 workspace 或每 job 獨立 DB，且把 graph 請求與期望節點限定在 fixture 集合，再考慮 workers。
- `document-composer.spec.ts` 的 `EMPTY_WORKSPACE` 是固定 ID `0199f100-0000-7000-8000-000000000004`；與 graph 的同名固定 workspace 相同，新增文件可能改 count／landing selection。
- `fixtures/phase3-identities.ts` 的 persona user IDs 與 `PHASE3_TEAM_ID` 為固定值。`phase3-identity-harness.spec.ts` 的 smoke grants case 為每例建立新 workspace，這例相對獨立；同檔 permission matrix 與其他治理 specs 使用固定 Team grants，不能單憑 persona 不同就認為不會互相改權限。
- 若選獨立 CI job shards，至少每 shard 有獨立 DB name、local／SSO build 目錄、server ports、fixture IDs／grant namespace；不能只改 `workers: 1`。隔離後再用個別 case setup／assertion timing 評估收益。

本階段輸出是候選與共享依賴清單，沒有宣稱第二／三階段 API setup、資料隔離或平行執行已完成。

## 獨立審查修正與暫留項目

審查發現 CLI `--reporter=line` 或 `--reporter line` 會覆蓋 config reporters，讓通過的測試缺少 `tests.json`，runner 因而報錯。改以 runner `--add-reporter` 強制加入必要 reporter，config 保留 list，既有 console reporter 選擇仍有效。HTML reporter 則會清空預設 `playwright-report/`、連同先前 UUID runs 一起刪掉；runner 現在保留 `playwright-report/html/` 作 HTML 輸出（覆蓋 `PLAYWRIGHT_HTML_OUTPUT_DIR`），保護同層 `e2e-runs/`。

新增的真實 CLI fixtures 先驗證 3 failed／10 passed（兩種 CLI 寫法找不到 `tests.json`、HTML 刪掉 previous runner.json），修正後 13 passed。修正後整套 unit：101 files、1476 tests passed，typecheck／lint 通過。實際 full 再跑：219 passed、0 failed／flaky、2 個既有 personal-mode skips，462.42 秒；221 個結果 file/title 再次逐項匹配 baseline catalog。測試對應 `19da2f5` 的 runner 修正內容。Artifact：`full/0ace9219-6429-4861-9f75-d159b0f78f26`。前面效能表是審查修正前的實際量測，並非宣稱修改 runner 後尚未重跑的結果。

暫留 Minor：若 SIGINT 在最後 `runner.json` 的非同步寫入期間到達，先前取消檢查已經完成，可能仍以 passed／exit 0 收尾。此時所有 tests 與 cleanup 已完成；影響最後的取消狀態紀錄，不會跳過 tests 或把 test failure 改為 success。未在本次單一 Important fix pass 中加入新的取消流程。
