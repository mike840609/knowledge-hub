# Personal Daily Driver (First Batch) — Implementation Plan

**English** | [繁體中文](2026-09-29-personal-daily-driver.zh-TW.md)

Chinese wikilinks below are preserved as literal input examples.

Corresponding specification: [`specs/2026-09-29-personal-daily-driver-design.md`](../specs/2026-09-29-personal-daily-driver-design.md). Decision IDs (D1…D13) and section references (§) refer to that specification.

## 0. How to Use This Plan

- **One PR per slice**, ordered per specification §10. Every PR tip must pass unit, integration, e2e, `tsc`, `eslint`, and `next build`; **every commit** must at least pass unit, typecheck, and lint. (Lesson from the previous batch: after rebase, none of the intermediate commits passed e2e, so reviewers could not trust commits individually.)
- Each task lists files to change, tests to write, and acceptance criteria. Its internal sequence is the recommended commit order.
- Per CLAUDE.md: record deviations from the specification rather than changing them silently. When a specification is wrong, correct it before code.
- DB tests require `make db-up`; run `make browsers` once before e2e.
- Convention reminder: no React unit tests for component behavior (the repository’s existing decision); unit-test pure functions and editor logic, and e2e-test user journeys. In e2e, locate the editor form with `page.locator("main form").first()` and match `Title` fields exactly.
