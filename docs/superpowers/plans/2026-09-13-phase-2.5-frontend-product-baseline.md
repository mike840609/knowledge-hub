# Phase 2.5 Frontend Product Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Phase 0–2 verification frontend with the long-lived Workspace-scoped Knowledge Hub product shell without changing existing knowledge, ingestion, revision, or authorization semantics.

**Architecture:** Next.js App Router becomes Workspace-scoped under `/w/:workspaceId`. Knowledge uses a persistent `Source Tree | Document | optional Inspector` layout, while Sources becomes a separate management surface for imports and source status. Existing application/domain contracts remain authoritative; only narrow read-model additions are allowed when the approved frontend needs data already stored by the existing model.

**Tech Stack:** Next.js 15, React 19, TypeScript, Tailwind CSS 3, Base UI primitives, Playwright, Vitest, MariaDB. Add `react-markdown`, `remark-gfm`, and `lucide-react`.

**Spec:** `docs/superpowers/specs/2026-09-13-phase-2.5-frontend-product-baseline-design.md`

## Global Constraints

- Frontend style: Linear/GitHub-inspired compact workbench.
- Use Base UI + Tailwind; do not introduce HeroUI or another opinionated visual framework.
- Use 4–6px radius, neutral 1px borders, minimal shadows, compact spacing, and sparse card usage.
- Primary navigation contains only `Knowledge` and `Sources`.
- No Home, Settings, Search, Editor, Publishing, MCP, Agent Memory, Favorites, Recent Documents, or Dark Mode.
- Canonical document route is `/w/:workspaceId/knowledge/:sourceId/:documentId`.
- Workspace, Source, and Document route identifiers remain UUIDs.
- Remove old `/knowledge` routes; no backward-compatibility redirects are required.
- One Source Tree is mounted at a time.
- Source order is deterministic by name.
- First readable Document follows existing Tree position order.
- Archived content is hidden by default.
- Inspector is closed by default.
- Desktop is split-pane; medium screens move Inspector to Drawer; `<1024px` uses full-page Document + Browse Drawer.
- Do not add Redux, Zustand, or another global state library.
- Preserve Phase 0–2 domain/application contracts unless a frontend requirement exposes a narrowly missing read-only projection.
- URL values are navigation context, never authorization evidence.
- Node version remains `>=20.9.0 <25`.

- [ ] **Step 3: Implement the helpers**

Use this ordering function:

```ts
const byPosition = (
  left: KnowledgeTreeNode,
  right: KnowledgeTreeNode,
): number =>
  left.item.position - right.item.position ||
  (left.item.id < right.item.id ? -1 : left.item.id > right.item.id ? 1 : 0);
```

`findFirstReadableDocument()` performs depth-first traversal over `buildKnowledgeTree(items)`.

`filterKnowledgeTree()` recursively retains ancestor folders whenever a descendant matches. An empty/whitespace query returns the original roots.
