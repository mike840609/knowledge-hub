# 在本機試兩個人的流程

[English](two-person-demo.md) | **繁體中文**

分享文件並在上面留言需要兩個人。公司部署以外的環境沒有登入功能，所以一台本機 server 永遠是固定的一個人。要當兩個人，就開兩台 server：**哪個 port 就代表哪個人。**

| 網址 | 身分 | 啟動指令 |
| --- | --- | --- |
| `http://127.0.0.1:3000` | 擁有者，即 `.env` 裡的 `KM_LOCAL_*` 身分 | `make dev` |
| `http://127.0.0.1:3001` | 「Local Reviewer」，第二個固定身分 | `make dev-reviewer` |

兩台 server 用同一個資料庫，所以其中一台建立的連結，另一台打得開。身分是各台 server 自己的設定，瀏覽器沒有任何方式可以改變它，因此不需要登入，也沒有切換身分的畫面。

## 開始之前

1. 在 `.env` 設定 `KM_REVIEW_WRITES_ENABLED=true`。預設是 `false`，這時看得到討論但不能新增。已經在跑的 server 要重啟才會生效。
2. 兩個終端機各啟動一台：

   ```sh
   make dev
   make dev-reviewer
   ```

3. **網址列請用 `127.0.0.1`，不要用 `localhost`。** 留言只在瀏覽器的來源等於 server 綁定的位址時才會被接受，而這兩種寫法是不同的來源。用 `localhost` 時頁面打得開、也讀得到討論，但新增留言會被拒絕（`REVIEW_ORIGIN_DENIED`）。

審閱者那台 server 第一次回應請求時，會在你的開發資料庫建立審閱者這個使用者和他自己的 My Space。系統沒有刪除使用者的功能，所以之後會一直存在。

## 流程

### 1. 擁有者撰寫並分享（port 3000）

1. 開啟 `http://127.0.0.1:3000`，進入 My Space。分享連結只能為個人工作區裡的文件建立。
2. 新增一篇文件，寫兩三段文字後儲存。
3. 開啟這篇文件，按頁首的 **Share link…**。在對話框按 **Create link**，再按 **Copy link**。

預期：新連結出現在對話框的清單裡，複製到的網址形如 `http://127.0.0.1:3000/s/<token>`。

### 2. 審閱者閱讀並留言（port 3001）

1. 把複製的網址裡的 `3000` 改成 `3001`，在另一個分頁開啟。
2. 選取某一段裡的文字，按 **Add comment**。
3. 輸入留言後送出。

預期：

- 看得到文件，**Shared by** 顯示擁有者的名字。
- 右側有 **Comments** 側欄。視窗窄於 1200px 時，它是一顆 **Open discussions** 按鈕，按了會開抽屜。
- 送出後：側欄出現這則討論，作者是 **Local Reviewer**；文件中被選取的文字有醒目標示，點標示會跳到對應的討論。

### 3. 擁有者回應（port 3000）

1. 回到 port 3000 的那篇文件並重新整理。
2. 捲到文件最底，展開 **Comments**。
3. 回覆這則討論，再試試標記為已解決、重新開啟與隱藏。

預期：看到審閱者的留言與它引用的段落；點討論會捲到那段文字。

### 4. 審閱者確認結果（port 3001）

1. 在分享頁重新整理討論。

預期：

- 看得到擁有者的回覆。
- 討論標為已解決後不能再回覆。
- 被隱藏的討論從審閱者的頁面消失。

## 也值得試的情境

- **文件改版。** 擁有者在 3000 編輯並儲存。審閱者不重新整理，直接在 3001 留言：會出現「Document changed」提示，要求先重新整理。
- **連結被撤銷。** 擁有者在 Share link 對話框按 **Revoke**。審閱者重新整理後看到「This link is not available」。
- **窄視窗。** 把審閱者的視窗縮到 1200px 以下，確認討論改由抽屜開啟。

## 這個做法看不到的

- **未登入的讀者**（「Sign in to add a comment.」）。本機身分永遠是已登入。
- **登入、登出與 session 過期。** 這個 repository 沒有它們的實作；session reader 由公司部署提供。
- **公司 SSO 群組**以及它們對應到的權限。

第一項由 E2E 測試涵蓋：它為每個固定角色各起一台 server，其中一個角色沒有 session（`tests/e2e/fixtures/phase3-server.ts`）。另外兩項只能在公司環境驗證。

## 運作方式

`make dev-reviewer` 就是 `make dev` 改了三樣東西：四個 `KM_LOCAL_*` 的值、port，以及 `KM_NEXT_DIST_DIR=.next-dev-reviewer`，讓兩台開發 server 不會互相覆蓋建置輸出。想再多一個人，就用同樣的方式再起一台，給它自己的值、port 與輸出目錄。`KM_LOCAL_ID` 必須是 UUID，而且它和 `KM_LOCAL_EMP_ID` 都不能是別的使用者的：若某個身分會改變既有 id 或員工編號的歸屬，server 會拒絕以它處理請求。
